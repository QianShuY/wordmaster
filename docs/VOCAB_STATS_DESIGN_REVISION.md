## 首批样例复审结论：重新定视觉方向

首批样例解决了数字字形、词条编号与日期位置的技术问题，但视觉仍停留在“旧卡片里换了内容”。`word-cardinal-2-front-desktop.png` 的主词周围留白过大，音标和标签过小；`word-attribute-2-back-desktop.png` 翻面后只剩一个米色释义盒，看不到词头；`stats-accuracy-calendar-desktop.png` 在大面积空白里放四个点，仍不像有意义的学习反馈。下轮先重做这三种样例，再讨论全量扩展。

### A. 学词界面改成一本可翻阅的词典页

- 设计关键词：**纸墨、编辑排版、安静、清晰**。保留暖纸与朱砂的品牌感，去掉厚重悬浮阴影、巨大的空白卡壳和“盒中盒”。视觉重点是词本身及释义，不是装饰。
- **词头始终在场**：前后状态都保留同一块词头区。桌面端词头左对齐，单词占据主要视觉重量；其下按顺序放独立音标、朗读按钮、词性和很轻的同形词标签。翻开释义时只展开下方内容，不再把整个卡片旋到另一面、把单词藏掉。
- `cardinal 2` 的大标题只写 `cardinal`。编号改成词头旁的低对比“同形词 II”或“词条 II”，不能与音标、词性挤在同一个胶囊里；`attribute 1/2` 各自的音标和朗读保持正确。读者第一眼看到词，第二眼看到发音，第三眼看到词性/差异。
- 正面高度由内容自然决定，桌面不人为撑出大片空白。主操作与“还不太熟/学会了”形成明确上下层级：查看释义是当前步骤，判定按钮在释义展开后才成为主焦点。手机版按同一阅读顺序纵向排，不缩成一张很小的桌面卡。
- 释义部分直接成为词典页的下半段：用细分隔线和留白区分词性，不再放大块米色填充背景。多义项每条一行；视觉上不重复印红色 `1.`、`2.`，可用细小序号、分隔线或无序号排版，但原顺序与屏幕阅读器语义必须保留。`cardinal 1` 应看出形容词与名词两组，`attribute 2` 应看出两个独立含义。
- `kbd` 快捷键提示缩到真正的辅助信息，不与主按钮文字争注意力；发音按钮使用清晰图标和可点击区域，不使用系统彩色 emoji 当视觉中心。

### B. 少量数据时取消大折线画布

- 目前近 30 天只有四个作答日。**不要画“四个点分布在 30 天大空白”**，即使日期位置数学上正确，视觉仍然松散。0 天用紧凑空态；1–6 个作答日用“学习记录”紧凑列表或短横条，标题说明“近 30 天 · 4 个学习日”，每行显示日期、正确/总数和百分比。列表本身就是图表，不再另放一张空 SVG。
- 至少有 7 个作答日时，才显示真正的时间趋势图。按真实日期布点，保留空档；纵轴 0–100%，日期标签清晰，图例与数值可通过触摸/键盘读取。若数据虽然满 7 天但非常稀疏，优先仍用列表或周汇总，避免拉出误导性的线。
- 折线图不做渐变大面积填充、假平滑或夸张描线动画。图表高度应与信息量相称；手机上不把 600px SVG 硬压成小字和小点。

### C. 数字与整体层级

- 首批数字字体方向保留，但重新排数值与单位：大数字统一视觉基线，`词`、`%`、`/ 209` 在独立次级层，不与主数值竞争。统计块减少厚边框和多余填充，主要靠对齐、留白、细线组织。
- 标题、数值、辅助说明应形成三档明显层级；辅助文字在手机上仍可读，不使用 10–11px 的灰色小字来换取“精致感”。

### 第二轮样例验收顺序

## 本轮要解决的问题

1. 数字使用 Georgia 等衬线字形，`0`、`6`、`8` 和百分号视觉基线、粗细不一致；分子与分母塞在一个粗体节点里，读起来像拼贴。
2. “正确率走势”把仅有作答的日期筛出来，再均匀铺满 30 天宽度。日期间隔被抹掉；缺少日期、百分比刻度、样本量，四个孤点被拉成一条误导性的长折线。
3. 原始词表中有 `cardinal 1` / `cardinal 2` 这类同形词编号，也有音标或词形变化混进词形/释义的脏行。把原始字段直接放大成标题、直接传给朗读，显得杂乱且可能读错。
4. 多义项的 `1. ... 2. ... 3. ...` 目前被当一整段纯文本渲染，没有词性与义项层级。

只改视觉而不处理数据会留下错题和朗读问题。本轮按下列顺序实现。

## 1. 数字系统：克制、对齐、可读

- 保留现有纸墨书房的背景、颜色和文字气质；数字区域单独使用清晰的无衬线数字字体栈，不再用 Georgia。所有统计数字加 `font-variant-numeric: lining-nums tabular-nums`，百分号、单位、分母使用独立元素和统一基线。
- “98 词”呈现为一个数值与小号单位；“10 / 209”把当前值作为主体、目标数作为次级信息，中间留稳定间距。数字不要用斜体、装饰性旋转或随机字重。
- 今日页、顶栏、学习数据页和词库进度共用一套数字 token：字号、字重、行高、数字特性。桌面和 360px 手机都验证 0/6/8/10/98/100%/209，不发生挤压或换行错位。
- 中文标签保持现有正文字体。大词条标题可继续有衬线，但编号与音标不能共享标题字号。

## 2. 正确率图：先诚实表达，再做美观

- 以真实日历日期定位 X 轴，而不是对 `daily.filter(d => d.total > 0)` 后的记录等距排布。Y 轴固定 0–100%，至少标出 0、50、100%；显示起止日期或按周标记。每个数据点的提示含日期、正确率、`正确次数/作答次数`。
- 作答日为 1–6 天时，不画折线或独立大画布；直接用紧凑逐日记录/短横条，显示日期、正确/总数和百分比；0 天为空态。数据足够时再绘制趋势。
- 连续日期之间可以连线；无作答的日期保留时间空档，不把跨多天的空白连接成连续学习。不能把无作答日当 0% 正确率。
- 线条和点用现有朱砂色，但降低视觉噪声：细线、有限网格、适量点标记。`preserveAspectRatio="none"` 会拉伸图形，需要改为可保持比例的响应式布局。不要用会虚构走势的平滑曲线。
- 鼠标、触摸与键盘都能读取逐日数据；图外有文字摘要/列表供辅助技术读取。尊重 `prefers-reduced-motion`，不依赖绘制动画才能看到线。

## 3. 词形、音标和朗读：清理显示，不破坏身份

- 保留数据库 `words.id`、学习进度、复习日志和卡牌数据；不得直接批量改 `word` 并导致唯一键冲突。先在只读副本上审计，建立可复现的分类/修复清单，再在迁移或显示适配层处理。
- 对已确认的**内置词库**同形词，如 `cardinal 1`、`cardinal 2`：大标题只显示 `cardinal`；词头旁用低对比“同形词 I/II”及独立词性标签。朗读和拼写目标都使用 `cardinal`，进度仍归原词条 ID。不要用全局正则剥掉所有末尾数字；用户自建的 `web 3` 等条目必须保留原文。
- 音标只在独立次级行出现一次，统一一对 `/ /` 或 `[ ]`，字号与颜色稳定；没有可靠音标则不造一个。音标混在词形/释义里的损坏行先分类、记录来源，再谨慎拆分。词形变化如过去式、复数形式应放在附注，不塞进主标题。
- 词条展示、朗读、拼写答案、释义选择、错题本、词库列表都调用同一份 `displayHeadword / pronunciation / answerHeadword / senseLabel` 数据视图，避免页面之间出现不同拼法。若清洗后答案不同，必须测试正确判题、重试与回炉。
- 存疑行保留原始内容供编辑或审计，不要静默丢失释义/音标，也不要猜测新释义。

## 4. 释义排版：结构清楚，原文可追溯

- 学词翻面以“词性小标签 + 释义列表”呈现。对明确连续的 `1. … 2. … 3. …` 拆成独立行；序号置于窄列，正文左边缘对齐，行距舒展。不同词性有分组标题或留白分隔，避免一整段粘连。
- 解析器仅处理有把握的编号格式，不要误拆小数、缩写、例句和括号中的数字。无法可靠解析时，以整段可读文本兜底，并加入审计清单。原始 meaning 字段不因排版而被重写。
- 默写、选择题、错题本及列表复用同一套安全转义/格式化规则；选择题内容不得因为插入 HTML 而改变比较答案的逻辑。手机屏幕保持自然换行，不使用固定高度裁剪长释义。
- 示例阅读顺序：大词头 `cardinal` → 独立发音行 `/ˈkɑːdɪnəl/` 与朗读 → 次级“名词 / 同形词 II” → 展开后词头仍在，释义区显示“红衣主教”。多义词分组分行，避免连续 `1. 主要的 2. 深红的 3. …` 文本，也避免醒目的红色编号占据视觉中心。

## 数据审计基线（生产库只读统计）

- 20,374 个词；带尾部 ` 1` / ` 2` 的词形约 499 条；词形内含音标/斜线等可疑符号约 98 条；释义中含 `1.`/`2.` 的约 4,965 条；另有约 258 条释义内嵌音标。计数用于估算范围，并不代表所有条目都可自动修复。
- 尾部编号主要来自英语专四专八与六级词库。样例：`cardinal 1`、`cardinal 2`、`attribute 1`、`attribute 2`。部分行是原始词表解析问题，须逐类处理。
- 任何清洗前后核对词库 6、单词 20,374、进度 94、答题日志 74、卡牌 62、收藏 3 的基线；用户真实数据库只读检查，所有写入先用隔离副本。
