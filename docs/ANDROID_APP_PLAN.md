# 墨词 Android 安装版：实施与验收框架

日期：2026-09-29  
状态：G0 的离线答题原型已在用户手机上确认正常，见 `docs/ANDROID_G0_REPORT.md`。G1 数据/规则和 G2 完整页面及本地服务接线均已实现，测试 APK 与记录分别见 `docs/ANDROID_G1_REPORT.md`、`docs/ANDROID_G2_REPORT.md`；Android 原生 instrumentation 尚未在设备/模拟器运行，G2 手机交互验收待用户进行。G3 数据转移/最终可发包尚未开始。当前优先级为 Android 手机；iPadOS、macOS 暂缓。发布签名暂不作为当前阶段验收项。

## 1. 要交付什么

交付一款**无需浏览器、无需电脑常驻服务、断网可完整学习**的 Android App。当前先用可安装的 debug APK 完成功能与实机验收，不办理发布签名；将来给朋友长期安装的正式包另列交付。首版覆盖：内置词库、学词、拼写默写、释义选择、词性判断、复习与错题、学习计划、统计、62 张卡牌与抽卡、自建/导入词库、本地备份和恢复。先做手机体验；平板适配可以在手机实机验收后单列，不用 iPad 模拟结果替代 Android 实机。

这次是现有墨词的移植与可靠性工程，不借机全面重做视觉。遵守 `docs/VOCAB_STATS_VISUAL_CORRECTION.md`：学词页紧凑；拼写页只有**一个可见且真实可输入的区域**；图表不靠大片空白或伪造折线填充。保留现有卡图、稀有度效果、词条修正、卡牌 ID 与历史收藏规则；不恢复科普内容、外部链接或在线素材。

**不包含：**应用商店上架、账号与云同步、联网词典、推送、付费、全量重写成 Flutter/React Native、iOS/macOS 构建。不要把“Android 工程能打开首页”当作完成。

## 2. 已核对的项目基线

- 前端是 `static/index.html`、`static/style.css`、`static/app.js` 的原生单页应用；`static/app.js` 直接调用 `/api/*`。页面已含手机断点和安全区域样式，但这不等于完成 Android 软键盘、返回键和真实 WebView 验证。
- 后端 `app/main.js` 是 Express API；`app/db.js` 使用 Node `node:sqlite`。Android WebView 不能直接运行这套 Node 服务。现有 `shared/domain.js` 包含复习间隔、学习配额、词条呈现等纯规则，可作为共享规则基础，但统计查询、选词、抽卡事务仍在服务器端，需要迁出或为移动端实现同一语义。
- 数据表含 `wordbooks`、`words`、`progress`、`review_log`、`cards`、`user_cards`、`card_draws`、`schema_meta`。当前数据库迁移到版本 5；`review_log.request_id` 用于答题去重，`card_draws.day` 用于每天一次抽卡。
- 内置种子是五本词库，代码目标上限合计约 20,500 条；卡册有 62 张本地原创 WebP，图片合计约 19.6 MB。图片、词表与文案均须离线打包。实际词条数以隔离环境运行种子后的统计为准，不按 README 旧数字猜测。
- 现有用户数据在 `data/wordmaster.db`；**不得把它复制进 APK、覆盖、清空或拿来跑可写测试**。测试用临时隔离库。只读核对旧数据时记录表行数、schema version 与卡牌 ID，不导出私人记录到交付材料。

## 3. 技术路线与边界

优先采用 **Capacitor + 现有 HTML/CSS/JS + Android 原生 SQLite 适配器**。它允许在 Windows 上用 Android Studio 构建 APK，也尽量复用现有页面。Capacitor v8 官方 Android 文档支持 Android API 24+，并通过 Android Studio 管理工程；实现时锁定一组相互兼容的 Capacitor、Gradle、Android SDK、JDK 和 SQLite 插件版本，在技术验证报告写清具体版本与最低 Android 版本。不要照搬某篇旧教程的 `targetSdk` 数字；按打包时官方要求和所选依赖定版。

```text
现有 UI（逐步整理 static/）
       │
       ▼
StudyService / BooksService / CardsService / StatsService / BackupService
       │                         │
       ├─ 共享纯规则 shared/domain.js
       │
       ├─ Web/Windows adapter → 现有 /api/* + Node SQLite
       └─ Android adapter → Capacitor bridge → 应用私有目录 SQLite
                                              └─ 本地打包的词库/卡图/文案
```

### 3.1 服务接口

先列出当前全部 `/api/*` 调用与响应，形成契约表，至少覆盖词库 CRUD/导入、学习队列、`learn`、`progress`、错题、统计、卡册、抽卡和隐藏卡文案。UI 只调用服务接口，不在各页面临时判断“是不是 Android”后各写一套流程。网页版 adapter 保持现有行为；Android adapter 调用本地持久化层。错误类型统一成可展示的“参数无效、记录不存在、保存失败、重复请求、当前无可抽卡”等，不把 SQLite 异常原样显示给用户。

对可重试的写操作约定请求 ID 和结果：答题 `request_id` 重试必须返回同一结算，不增加两次统计；相同 ID 换内容要报冲突。学词标记必须幂等；抽卡在事务中验证今日资格、随机选卡、写入 `user_cards` 与 `card_draws`，重复触发只会得到“今日已抽”状态。服务层应让保存完成后 UI 再前进；失败时保留当前题与已输入内容，允许重试。

### 3.2 SQLite 与种子

Android 数据库存应用私有目录，不用 WebView `localStorage` 存学习记录。SQLite 方案可选受维护的 Capacitor 插件或小型原生桥接；实现 agent 必须先提供：许可证、维护/兼容状态、事务与批量插入能力、Android 真机构建证据、失败恢复行为。不要在未验证前把整个数据库层绑定到某个插件。

用明确的 `schema_version` 迁移，旧版到新版每一步可重复检查。首次安装将五本内置词库、卡牌元数据导入本机库，种子完成标志与写入处在可恢复的事务中。内置书和卡牌采用稳定 key 映射；卡牌旧 ID、`palette`、隐藏卡条件保持一致。后续版本不能因为重新 seed 而重排 ID、覆盖自建词或清除进度。大词表应分批导入并报告进度，启动时不能长期白屏；中断后重启能安全续建或回滚重试。

**跨设备迁移风险：**当前数据库的自增词条 ID 不是天然的跨设备身份。实现导入/导出前，先提交稳定标识方案：内置词条可用内置书稳定 key + 原始词条稳定 key，并对同形词做区分；自建词库和单词使用持久 UUID。旧库 ID 到新 key 的映射应有审计表或迁移报告，不能只按词头猜测，也不能把自建词误并入内置词。

### 3.3 规则与日期

移动端复用 `shared/domain.js` 的纯规则；把服务器侧的“取到期词、新词额度、统计口径、抽卡权重”变成可对照的查询/服务，不允许 Web 与 Android 各自悄悄变更规则。沿用 1/2/4/7/15/30 天复习和答错 10 分钟回炉口径。对**本地日**、午夜跨日、设备时区变化、手动改时间、应用从后台恢复补做测试；每日抽卡资格与统计用同一日期口径。随机抽卡测试注入固定随机源，生产保留实际随机行为。

### 3.4 备份与恢复

首版必须有用户可操作的“导出备份”和“从文件恢复”：通过 Android 系统文件选择/分享机制存取文件，不索取宽泛存储权限。备份使用带 `format_version`、导出时间和条目计数的可校验格式，覆盖自建词库/词条、学习进度、答题日志、卡牌收藏、抽卡记录和必要设置。导入先解析和校验，再显示摘要与覆盖/合并策略，最后在事务中提交；损坏文件、未来版本文件、重复导入和中途失败均不得破坏现有数据。Windows 旧库转移至少用隔离副本做一次全量往返核对。

首版以**应用内显式备份**为可验收保障。Android 系统 Auto Backup 的配置要明确记录并测试；若暂不支持可靠恢复，就在 manifest/数据提取规则中关掉自动云备份与设备转移，避免只恢复一半表或意外将个人学习数据传云端。卸载会删除应用私有数据，交付说明必须提示先导出备份。

## 4. Android 交互与性能要求

- 首页、学习、词库、卡册、统计等现有功能均可触摸完成；系统返回键先关闭弹层/键盘，再回到上一级，学习中退出需合理处理未保存结果，不得误丢或重复提交。应用暂停、来电、杀进程后重开仍保留已确认保存的进度。
- 拼写页保留一个视觉输入区，底层是**真实可聚焦输入控件**；点击字母格可以调起 Gboard/厂商输入法，粘贴、退格、光标移动、中文输入法组合态、外接键盘均可用。字母只显示一次；长词、短语、连字符和撇号不横向溢出。软键盘弹出后确认/跳过等主操作可触达。
- 按 360、390、430dp 宽度先验收，覆盖大字设置、横屏、不同系统导航方式、状态栏/手势区域；触控目标以 Android 常见 48dp 为基准。学词页保持受控内容宽度，不把桌面留白搬进手机。
- 卡面图片主导，N/R/SR/UR 一眼可辨；62 张 WebP 和卡文案内置。SR/UR 动效支持 `prefers-reduced-motion` 或平台减少动态效果，动效/图片加载失败仍可读卡、抽卡。不要引入远程图源、外链或需要联网才能看的动态素材。
- 发音先实测 Android System WebView 中 `speechSynthesis` 可用性、离线语音包依赖与失败情况；不可靠时设计 Android TTS 原生桥接和无语音包提示。无发音服务时练习仍可继续。
- 图片懒加载与固定比例；在目标实机量测首启种子耗时、冷启动、卡册滚动、APK 体积、内存。没有实测前不承诺具体帧率或秒数；若词库初始化过慢，提交分批/预置只读种子库的对比数据后再选方案。

## 5. 安全与发布包

- 正式包只加载随 APK 打包的本地资源；禁止设置远程 `server.url` 作为正式入口，也不启动 Express 或请求电脑的 `localhost:3456`。梳理 WebView 导航白名单、CSP 与所有资源请求，确认飞行模式完整可用。只申请实际用到的 Android 权限；备份走系统文件接口，不为方便而授予整盘读写。
- 固定唯一 application ID（例名只作示意，须确认未占用后再定）、`versionCode`、`versionName`。当前阶段使用 Android 工具链自动签署的 debug 构建验证功能，不需要用户创建密钥或办理账号；不要把 debug 包称为正式发布包。将来正式分发时再配置发布密钥、不可调试的 `release` 变体和更新路径；任何密钥都不得提交仓库。
- 功能验收至少交一份可安装 debug APK，附 SHA-256、版本信息、最低 Android 版本、安装步骤和备份提示。明确标注它是测试包；在真实 Android 手机上从“收到文件”走到安装、离线学习、退出重开、覆盖更新。正式分发包作为后续独立验收，不阻塞当前开发。
- Google 的开发者验证新规则在 2026-09-30 先针对巴西、印尼、新加坡、泰国的参与商店与认证设备生效，并计划在 2027 扩大范围。**当前不能把“自签 APK 永久对所有安卓机无限制直装”写成承诺。**若只给少量亲友，可评估官方免费“有限分发”账号：上限 20 台、需用户授权设备并注册包名；具体是否需要按收件人所在地/设备渠道在发包时复核。未注册 App 的高级侧载流程也是另一条路径，不能替朋友默默绕开系统提示。

## 6. 按阶段交付，逐关审核

### G0：技术验证和合同

只做最小 Android 工程与数据方案，不移植全功能。提交选定版本与依赖许可证、完整 `/api/*` → Service 接口矩阵、数据库/备份稳定 key 设计。做一个**本地** Android SQLite 垂直切片：首启建库 → 显示一词 → 提交一题 → 强制关闭重开 → 进度仍在；打开飞行模式重做。证明没有电脑服务和远程网页入口。交 Android Studio 工程、debug 构建日志与模拟器/真机类型标识；本关不处理发布签名。

### G1：完整本地数据与规则

**实施状态（2026-09-29）：**G1 数据与规则层已实现，自动测试结果和设备验证限制见 `docs/ANDROID_G1_REPORT.md`。等 G1 审阅与 Android 实机复核后再进入 G2。

迁入五本词库、进度、日志、计划、错题、统计、卡牌表和 62 张资源。用同一份固定样例数据对照 Web/Android：选词、配额、四种练习判定、间隔、错题回炉、统计、抽卡资格及权重边界。针对答题重复请求、写入失败、首启中断、升级迁移写有意义的自动测试。交隔离库的表计数和事务回滚记录。

### G2：Android 学习体验

**实施状态（2026-09-29）：**已接入完整现有页面和 Android 本地 SQLite 服务；根据用户真机截图修正手机学习卡片留白、上/左右滑动、拼写输入焦点与单击操作、抽卡入口和热力图初始位置。更新测试包为 `1.2.1-g2`；修正后的软键盘、手势、返回键与不同屏宽仍待真机复核，详情见 `docs/ANDROID_G2_REPORT.md`。

完成完整四模式、词库管理、卡册和统计。交 360/390/430dp 截图、键盘弹出前后录屏、卡面等级和减少动态效果录屏、系统返回键与后台恢复结果。至少一台 Android 真机验证 Gboard/常见输入法、粘贴、外接键盘（若无外接键盘明确标“未验收”）、语音、断网。视觉以 `VOCAB_STATS_VISUAL_CORRECTION.md` 为准；先交关键样例给用户确认，不擅自换整套风格。

### G3：数据转移与可发包验收

用隔离的 Windows 库副本导出并在 Android 导入，核对词库、自建词、进度、日志、拥有卡、每日抽卡记录数量与稳定 ID 映射；验证坏文件不改数据。交测试 APK，核对版本、SHA-256、无生产 DB/密钥/开发 URL。朋友或另一位测试者按交付说明在真实手机上**不用 ADB/开发工具**安装；执行首次启动、飞行模式完整学习、抽卡、导出、覆盖升级、重开，提供结果和问题清单。若缺真机，只能写“代码完成，未通过手机安装验收”。正式发布包与专属发布密钥待用户需要长期分发时另行处理。

**每关提交格式：**改动清单、架构决定、命令与实际输出、隔离测试证据、截图/录屏、数据库数量对比、权限和网络请求清单、已知限制。上一关未审核通过，不得以“先全做了”替代关卡审查。

## 7. 一票否决项

直接把线上/本机网页套壳而 Android 断网不可学；发 debug APK 冒充正式发布包；安装包内含真实 `wordmaster.db`、签名私钥、开发机地址或外链素材；升级/备份丢进度和收藏；拼写有两个输入区或不能唤起软键盘；保存失败却进入下一题；重复提交增加两次统计、一天抽多次；只给模拟器截图声称实机通过；未获用户确认即把整套 UI 再次大改。

## 8. 可直接转发给实现 agent 的首轮指令

> 请按 `docs/ANDROID_APP_PLAN.md` 实施墨词 Android 安装版。本轮**只做 G0**，先读 `README.md`、`docs/VOCAB_STATS_VISUAL_CORRECTION.md`、`app/main.js`、`app/db.js`、`shared/domain.js`、`static/app.js`。提交 `/api/*` 接口矩阵、Android SQLite/稳定 key/备份设计和依赖版本，再做“首启 → 一词 → 提交 → 强制退出重开 → 离线保留进度”的最小 Android 工程。不得修改生产数据库，不得重做 UI，不得提前扩展全功能。交构建命令、实际运行证据、隔离测试库路径和仍需确认的事项，等 G0 审核通过再做 G1。
