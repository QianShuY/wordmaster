## 1. 目标与已确定需求

将墨词推进到内容可靠、复习有效、首章有结局、全站流畅的正式 Windows 日用版本。范围包括：中考入口替换高考；四级、六级、考研、专四专八全量语言审校和双语例句；学习复习可靠性；首章通关与纪念成果；全站体验和性能；最终发布。

用户明确要求连续完成，不每做一小轮就要求用户回复“继续”。CET6 独立项目接入继续后置。不能用测试通过、草稿数量或单义项检查冒充整轮完成。

当前用户真实学习、计划、收藏和旅程记录必须保留。曾经的重置授权已经结束。仓库不包含本机真实数据库、备份和本轮临时 QA 数据；本地文件已保留，仅取消版本跟踪。历史提交曾跟踪数据库，本次没有重写历史，不能宣称历史数据已从 Git 清除。

## 3. 运行与初始检查

项目为 Node.js + Express + SQLite、原生 HTML/CSS/JS，没有 React 或 Vite。Node 24 提供 node:sqlite；云端 Linux 不运行 runtime/node.exe 或 WordMaster.exe。

```sh
node --version
npm ci --no-audit --no-fund
npm test
node --check static/app.js
node scripts/audit-model-task-progress.js
```

使用 Node 24。启动预览用 `npm start`，默认访问 localhost:3456；在隔离环境可设 `WORDMASTER_DB_PATH`、`PORT` 和 `WORDMASTER_HOST`。云端没有用户真实数据，首次启动会创建新的测试用数据库。正式源码中默认数据库路径为 data/wordmaster.db，必须保持被 Git 忽略。

交接前本地及合并远端后的完整测试均为 157 项通过、0 失败；新检出验证结果会记入 docs/GITHUB_HANDOFF_CHECK_2026-10-16.md。未执行的 Windows/浏览器检查必须如实列出，不能用 Linux 单测代替 Windows EXE 验收。

禁止执行 rebuild-vocabulary.js --apply-reset；禁止上传 data/、本地备份、环境变量文件、临时数据库和个人学习数据。需内容更新时参考 app/content-upgrade.js 的在线备份、事务验证和来源字段绑定机制。

## 4. 已实现的基线，不要推倒重写

- 新桌面任务每组最多十词，按认识→选择巩固→拼写完成，再进入下一组；旧断点保留原轮次。分组位置与累计进度可恢复，最后一组前不请求当日旅行结算。
- 学习卡片上方“持续回忆中／下次复习”整块提示已移除。拼写提供主动“听读音提示”及 ↑，旧词不自动朗读、不显示首字母。
- 旧词词义→拼写两步复习，错误强化与跨日重开保护，间隔 1/2/4/7/15/30 天；不会因连续选择正确就当作长期掌握。
- 第一章十四关、每天计划完成推进一天、营地与逐步线索、正式 Boss 战斗服务端重放、首通来信和渡雾者之印、重复结算幂等。
- 全站手账主题与卡牌陈列；旅行地图保留氛围动画和音乐。不要暴露 Boss 作为首屏剧透，不要重新加入嘈杂环境声或上下翻转的大雁。
- 词库来源身份、拼写规则来源哈希、历史只读库、内容增量更新失败回退和首页重试机制。
- Windows 候选做过隔离结构/内容升级检查，但最终完整内容正式发布仍未完成。

## 5. 第一优先：接续三个模型的半成品，先校验再审核

输入在 docs/model-tasks-20261015/，结果在 docs/model-task-results/，全部包含在交接分支，包括未满一百条的进行中文件、进度和旧版本副本。它们只是提交建议，不是正式种子数据。不要重新从零生成全部内容，不要删掉半成品，也不要把旧版本副本当作额外已完成量。

分工：A 四级全量、六级全量、tem-001～022；B 考研全量、高考剩余单元、tem-023～036；C tem-037～125。范围互不重复，共 268 份、26,612 条输入，其中保留四库 24,555 条和待审高考 2,057 单元。

执行步骤：

1. 运行审核进度脚本，以实际 result.json 为准，不只信 progress.json 或 summary.md。输出默认在 output/refinement/，该目录不入库；需交付审计摘要请另存 docs/。
2. 校验 JSON、task_id、输入 SHA256、行数、顺序、identity 与 original。进行中文件可只有前 N 条；缺哈希不能通过完整提交验收。先保留问题清单，不改输入快照或伪造哈希。
3. 区分 source-checked（模型自报查证）、needs-review、缺证据、空例句、错义项、同形词、词性和 IPA 疑点。模型声称访问过词典不等于主代理已查证。批量草稿量不得作为语言审核通过数。
4. 用原始词典实际核对疑点，普通例句也检查自然性、语法、目标义项和翻译。不得通过自动拼接网址或无依据删除多义项“补完”。打不开词典时保留 needs-review。
5. 优先利用已正确产出的结果，再接续未完成任务；每份产物保留输入身份、证据和处理结果。记录 accepted、rejected、needs-review，附理由；accepted 必须有足够证据，不要降低标准以提高百分比。

目前已知质量风险：C 大量结果明确缺词典依据，属于原创例句草稿；B 部分进行中条目尚无输入哈希。实际数量随本机模型继续工作变化，以当前仓库快照为准。交接后本机后续结果不会自动出现在 GitHub，需要另行同步，不假定实时共享目录。

## 6. 第二优先：安全整合词库与完成高考替换

主要入口：app/vocabulary.js、shared/content-batch.js、shared/content-corrections.js、shared/source-sense-binding.js、app/content-maintenance.js、app/content-upgrade.js、scripts/release-data-check.js。

目前支持 16 个明确编号义项的来源绑定，并有防串义项测试；仅有源码绑定，不代表已写入本机旧库。词性修订的通用补丁链和编号义项的更多审核仍待完善。请以明确旧字段→新字段允许清单处理 POS、释义、IPA 和例句，兼容先前补丁，拒绝用户手改内容被覆盖；同时更新独立升级验证器，不得只让应用代码自行证明安全。

高考当前已有 1,054 / 3,111 个教学单元的选定义项稿，剩余 2,057，正式安装 0。源 PDF 提取为 3,099 源条目，原文声明 3,100，拆分后为 3,111 单元；不得补造条目来凑数。版本、转载一致性、使用条件和计数差异仍需核实，见 docs/vocabulary-audit/GAOKAO_SOURCE_EVIDENCE_2026-10-15.md。不要用更早的课程标准偷换目标。

完成教学内容和来源核验后，先在一次性副本执行替换预演及回滚检查。新高考独立建库，不给旧 book_id 换内容冒充迁移；有旧记录或编辑的中考保留历史只读。保留学习、计划、收藏、旅程、词条身份和自建词，验证重复运行幂等、故障回滚与异常恢复。计划进度不要自动迁到新高考库。

## 7. 第三优先：核心完整操作链与性能

- 浏览器真实走通 23 词的 10/10/3 三轮流程，检查错误重测、最后不足十词、断点重开、跨日过期、词性或拼写不可用、旧断点兼容、主动读音和焦点。隔离数据，禁止在用户数据库模拟答案。
- 正式 Boss 胜利→服务端结算→结局跳转→纪念印章→刷新再开→再次挑战不覆盖首次记录。补充失败、复活、保存失败后重试及不可伪造状态。已有结局页夹具检查不等于整条操作链已验收。
- 检查远端合并后的错题练习结算、异步请求旧响应保护、无学习记录显示“—”、学习数据范围与主题一致性。不得回退到“连续答对三次等于长期掌握”的宣传。
- 覆盖今日、词库、学习、数据、卡册、旅行、地图、营地、战斗、结局的正常/空/错误状态；桌面和窄屏无横向溢出、坏图和未捕获错误。
- 记录首屏、切页、地图后台暂停、长时间内存/DOM/监听器变化。当前约五分钟无头样本不能代替多小时真实桌面体验或 GPU 结论。
