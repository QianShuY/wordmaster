# 墨词：网页版优化、手机版与 Mac 版实施框架

> 交给实现 agent 的任务书。本文只定义目标、边界和验收；当前仓库中的应用代码尚未按本文修改。

## 1. 当前基线与目标

- 现状：`app/main.js` 是 Express API，`app/db.js` 使用 `node:sqlite`，`static/` 是原生 HTML/CSS/JS 单页应用；Windows 版依靠本机 Node 服务。数据存于 `data/wordmaster.db`。卡册现有 62 张原创 WebP，卡牌 ID 与已有收藏必须保持稳定。
- 目标平台：现有 Windows/浏览器、macOS 桌面安装版、iOS 与 Android 手机安装版。第一阶段不做云账号或自动跨设备同步；各设备离线使用，通过显式导出/导入转移数据。
- 产品目标：一打开就知道今天该学什么；手机能完成全部四种学习模式；答题进度可靠保存；卡牌是学习后的奖励；桌面端保留高效键盘操作。
- 本轮不引入付费、社交、排行榜或新卡牌生成。若以后要跨设备实时同步，单独设计账号、服务端、冲突合并和隐私方案，不把本地数据库直接暴露到局域网/公网。

## 2. 架构决策

### 2.1 共用与平台边界

```text
共享 UI（现有 static/，逐步模块化）
    ↓
StudyService / BookService / CardService / BackupService 接口
    ↓
纯 JS 学习规则：配额、复习排期、题目判定、奖励资格、统计口径
    ↓
Web/Windows/Mac：本机服务 + SQLite
iOS/Android：Capacitor 容器 + 本机 SQLite 适配器
```

- 共用页面、设计 token、卡牌资源和**纯规则函数**，不要维护三套相互分叉的学习逻辑。
- Web/Windows 暂保留现有 Express API。UI 逐步改为调用服务接口，浏览器适配器请求 `/api/*`。
- Mac 优先做 Electron 技术验证：用现有本机服务和 SQLite，数据库移到应用的用户数据目录；仅监听 `127.0.0.1` 的随机空闲端口。验证当前 Electron 运行时是否可用 `node:sqlite`、资源路径和退出清理。若验证不通过，给出最小替代方案与证据，再扩展包装代码。回环地址仍需校验请求来源/会话令牌，避免其他本机页面直接调用写入接口。
- 手机端优先采用 Capacitor 复用 Web UI，但**不能假定 Express/Node 服务能在 iOS/Android WebView 内运行**。建立移动端持久化适配器，并让相同的领域规则服务它。SQLite 插件选型必须记录维护状态、许可证、iOS/Android 构建验证结果。禁止把全部学习数据仅存 `localStorage`。
- 词库种子和卡牌元数据要有版本号与幂等迁移。升级不得重置已有 `progress`、`review_log`、`user_cards`、自建词库或卡牌 ID。
- 把当前页面引用的在线字体打包为本地资源或准备系统字体回退；手机和 Mac 的离线验收不能依赖 Google Fonts。

### 2.2 数据契约

- 保留现有词库、单词、学习进度、答题日志、卡册关系。定义 `schema_version`，迁移按版本执行并可从旧库升级。
- 定义 `BackupService.export()` / `import()`：版本化 JSON，至少包含自建词库和单词、学习进度、答题日志、卡牌收藏、设置；导入先校验，再预览摘要，再事务提交。损坏或未来版本的文件给明确错误，原数据不变。
- 词库与卡牌使用稳定标识；导入时不能仅凭自增 ID 猜测跨设备对应关系。内置词库/卡牌应有稳定 key；自建内容应有持久 UUID。实现 agent 先提交映射/迁移设计供审核。
- `POST /api/progress` 的保存与日志写入应处于同一事务；提交应有去重标识，避免重试产生双倍统计或抽卡资格。日期口径统一为设备本地日，并给跨日边界测试。
- 现有本地单用户模型保持单用户。以后若开放在线多用户，必须另设身份和数据隔离层，不直接共用当前全局表。

## 3. 分阶段实施任务

每阶段单独提交改动和验收材料，通过审核再做下一阶段。不要把所有平台、UI 和数据迁移塞进一次提交。

### A. 基线与学习可靠性（所有平台的前置任务）

**实现**

1. 为现有 `data/wordmaster.db` 做可恢复备份，记录基线数量：词库、进度、日志、已拥有卡牌；不得提交用户真实数据库。
2. 将配额、复习排期、奖励资格、答题结算提取为可在 Node 和浏览器运行的纯函数，并为日期/边界/重复提交写针对性测试。
3. 学习页在保存成功后才进入下一题；保存失败保留当前题和判定结果，显示「重试保存」，重复点击不会重复记账。退出和重新打开后进度一致。
4. 修正本轮统计：首次答对、回炉后答对、放弃/答错分别记录；学习模式的“还不太熟”不应让进度超过 100%。完成页文案与真实统计一致。
5. 保留现有 Windows 启动方式和 API；卡牌 ID、已拥有卡牌数量不变。

**验收**：断开本地服务/模拟写入失败后，页面不假装保存成功；恢复后重试只记一次。旧数据库升级后统计、收藏与自建词库均不丢失。

### B. 手机优先的学习界面（先在浏览器完成，再接原生容器）

**页面框架**

- 首页：今日待复习、今日新词、单一主按钮「继续学习」；词库管理收进次级区域。首次使用只引导选词库、设轻量目标、学 3 个词并做一次默写。
- 学习页：顶部只有退出、进度、模式；中间是一张题卡；底部是主要操作区，避开安全区域和软键盘。答题后明确显示正确答案和下次动作。
- 卡册：收集进度、距离抽卡还差几次有效作答、可抽状态、卡牌网格与详情。未拥有的卡牌可以显示轮廓和解锁规则，但不泄露完整卡面。
- 数据页：今天、近 7/30 天、困难词优先；图表可触摸读取数值，空状态给可执行建议。
- 导航：手机底部最多 4 个一级入口（今日、词库、卡册、我的/数据）；学习页进入专注模式，返回路径明确。平板/桌面可继续顶部导航。

**交互与可访问性**

1. 拼写题以真实可聚焦输入框接收软键盘与粘贴/删除，字母格仅做可视化；仍支持桌面快捷键。测试中英文输入法切换、长词、连字符与撇号、键盘弹起、旋转屏幕。
2. 选择题、翻卡、卡牌详情全部使用可聚焦的语义控件；补键盘焦点、屏幕阅读器标签。桌面快捷键仅在非输入状态触发。
3. 手机点击区域至少 44×44pt（Android 目标 48×48dp）；正文字号与系统字体放大后不裁切。无横向溢出，底部内容不被手势区/导航遮挡。
4. 网络/数据库操作有加载、失败和可重试状态。发音失败时给轻提示，不中断答题。

**验收尺寸**：360×800、390×844、430×932 的手机视口；横屏与平板；真实 Android 和 iPhone 至少各一台。纯浏览器模拟只能算预验收，不能替代软键盘实机验证。

### C. 卡牌美术与动效

**美术规范**

- 保留现有 62 张生成图和卡牌 ID。卡面改成固定的“插画区 + 底部信息区”，避免标题长期盖在主体画面上；小尺寸也能读清名称和稀有度。
- 用「墨词」现有纸色、墨色、朱砂、松绿做主系统。稀有度用边框、纹理、局部光泽分层，避免每张卡都持续闪烁。不要把界面整体改成糖果风或随机主题。
- 图标使用同一套 SVG 线条风格；中文文本优先可读性。图片离线可用，列表懒加载，卡面保持固定比例以免跳动。

**动效规范**

- 答题反馈约 150–250ms；页面切换约 200–300ms；抽卡高潮约 0.8–1.2s，由「墨迹汇聚 → 翻卡 → 稀有度出现」构成。动效表达状态变化，不延迟下一题操作。
- 同屏只让焦点卡牌显著运动；常驻背景动效节制。遵从 `prefers-reduced-motion`，减少动效时所有功能仍完整。
- 动效只使用 `transform`/`opacity` 等较低成本属性为主；低端手机卡册滚动无明显卡顿。

**验收**：普通、SR、UR、未解锁、抽到隐藏卡各交付截图/短录屏；文字对比度可读；减少动态效果模式可正常完成抽卡。

### D. Mac 桌面版

1. 先做 Electron 最小验证分支：启动、学习一题、退出重开、数据保持、卡图与发音可用；记录 Electron/Node 版本与 `node:sqlite` 兼容性。
2. 正式版把数据库放在用户数据目录，升级不能覆盖；窗口恢复到合理尺寸，最小尺寸下不裁切学习操作；支持菜单、退出、重新打开和桌面快捷键。
3. 只加载本机内容；渲染进程禁用 Node 集成、启用上下文隔离和沙箱；限制导航与新窗口、加 CSP。若启动本机 HTTP 服务，监听回环地址并在退出时关闭。
4. 提供本机导出/导入；从 Windows 备份文件导入后，词库、进度、收藏数量一致。
5. 在真实 macOS 上验证 Apple Silicon；若承诺 Intel 支持，再验证 x64。分发版的签名、公证、安装与首次启动需在 Mac 上完成，不用 Windows 上的打包结果冒充已验收。

**验收**：交付可安装产物、Mac 实测记录、数据导入前后数量和关键页面截图。发布给普通用户前完成签名与公证。

### E. iOS / Android 安装版

1. 在 B 阶段手机界面通过后接 Capacitor，先打通一个端到端路径：首次启动 → 内置词库 → 学词 → 默写 → 关闭重开 → 复习进度仍在 → 抽卡。
2. 本机 SQLite 适配器实现与 Web 服务层相同的行为；卡牌、词库、排期和奖励规则调用共享纯函数。离线完成核心学习流程，不要求本机运行 Express。
3. 发音使用平台可用语音能力，失败时可继续学习；处理 App 暂停/恢复、系统时间变化和日界线。
4. 系统分享/文件选择器用于备份导出与导入；导入预览与回滚规则同 2.2。
5. iOS/Android 分别验证安装、升级、卸载重装前的备份恢复、软键盘、手势返回、权限说明、安全区域、系统字体放大。

**验收**：真实设备录屏和安装包；开启飞行模式完成完整学习与抽卡；与同一份测试备份数据的 Web/Mac 结果一致。

## 4. 审核规则与交付格式

每个任务提交时给审核者以下材料：

1. 改动文件清单、设计决定、未完成项；涉及存储时附迁移/回滚说明。
2. 可运行命令与实际结果；针对性自动测试结果。不要用“应该能运行”替代实测。
3. 关键页面桌面/手机截图；动效给录屏；Mac/iOS/Android 标明真实设备还是模拟器。
4. 旧数据对比：词库、自建单词、进度、答题日志、已拥有卡牌数量；失败重试和跨日结果。
5. 明确指出新增依赖、许可证、安装包体积变化和外部网络请求。

**否决条件**：丢失旧数据；手机不能输入拼写；保存失败仍显示完成；抽卡重复扣/重复得；只在模拟器验证却宣称实机通过；Mac/手机版依赖公网才能学习；卡牌图片恢复为未经确认的第三方素材。
