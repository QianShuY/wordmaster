# 首页与栏目切换性能第一批

## 本批变更

- 首页路由立即启动，主题、卡牌文案并行初始化。主题资源失败仍可进入学习，不再把主题请求串在首页前面。
- 桌面首页改用 `/api/desktop/mistakes/count`，只读取错词数量。完整错词接口继续供复习模块使用，Android 接口不变。
- 共享同一 URL 的同时进行中的 JSON GET 请求，完成即释放，不做跨时间缓存。写入前后清空共享队列；写入请求本身绝不合并。每位读取者得到独立对象，卡册预览修改不会污染真实收藏状态。
- 首页、卡册、首页成长和陈列内容使用路由版本检查，离开栏目后的旧结果不再覆盖新页面加载提示或渲染内容。

## 验证结果

- 全量测试 93 项通过，0 失败。新增覆盖并发读取、独立收藏对象、写入边界、失败后重试；错词数量与完整错词清单一致。
- 浏览器只读验证首页、卡册、统计、旅行栏目与返回首页；保留图书馆主题，实际收藏 5 张、旅程 1/14 正确，未捕获控制台错误。
- 真实数据库保护表全部行 SHA256 与本批前一致，完整性检查 ok，外键检查无异常。没有代用户提交答案、抽卡或通过关卡。
- 本地服务已重启加载新版。截图级视觉验收、Windows 发行包验收尚未完成。

## 测量与边界

同一正式数据库、相同错词口径（14 个），循环交替 GET 两个接口各 10 次，排除每个接口首样本，保留 9 个温请求样本。原始数据位于 `output/refinement/home-payload-performance-20261013.json`。

| 首页所需数据 | 响应体 | 温请求中位数 |
| --- | ---: | ---: |
| 原完整错词清单 | 13,708 字节 | 13.18ms |
| 新错词计数 | 12 字节 | 14.79ms |

请求体积和内容处理量明显减少，但本机温请求耗时存在抖动，计数接口在此样本中的耗时中位数没有改善，不能据此宣称网络延迟降低。也没有将 API 测量作为冷启动、浏览器首屏、动画帧率或 EXE 性能成果。

启动优化移除了首页对主题初始化完成的前置依赖，尚未量化冷启动改善。并发请求合并仅处理重叠请求，不保证整个会话只请求一次，也不缓存学习进度。
