## 产品目标

学习数据页除了报数，还要回答：**最近的表现如何？现在哪里需要复习？建议基于什么？**

仅使用本地 SQLite 已有的 `words`、`progress`、`review_log`，不训练模型、不联网提交单词、不修改复习算法、无新增数据库迁移。

### 口径必须真实

| 指标 | 来源 | 定义 |
|------|------|------|
| 新词学习覆盖率 | `words` + `progress` | 已有学习进度的不同词数 ÷ 词库总词数。**不等于掌握率** |
| 已掌握词 | `progress` | `streak >= 3` 的不同词数 |
| 需要回炉的词 | `progress` | `wrong > 0 AND streak < 3` |
| 到期复习 | `progress` | `next_due <= 当前本地时间` 且不为空 |
| 近 7 日正确率 | `review_log` | 今天及之前六天，所有实际作答记录的答对数 ÷ 作答次数。重试也算作答 |
| 上一个 7 日正确率 | `review_log` | 7–13 天前七个日历日，同一口径 |
| 变化 | 两个 7 日正确率 | **百分点差值**。任一期无作答则显示“暂无对照”，**不能写作 0%** |
| 关注单词排序 | `progress` | 已到期词优先，再按错题次数降序；显示原因，不虚构记忆概率 |

### 规则建议优先级

1. 有到期复习：**先完成到期复习**，因为间隔由已有遗忘曲线规定。
2. 否则有错题：**回到错题本**，不要提前强制改变原定复习时间。
3. 否则还有新词：**继续当前学习计划**。
4. 否则：明确写没有待处理任务 / 近期无作答，不能伪造诊断。

全词库视图的到期复习建议会先跳到「今日」选词库；选择具体词库时才可直接进入它的今日任务。错题入口会保留用户已选的词库范围，只有全库视图才进入全部词库错题。

## 本地 Agent 复测任务

**必须在临时 SQLite 数据库中操作，先检查 Git 工作区状态，不能强制重置当前工作或覆盖生产数据库。**

1. 拉取最新 `feat/desktop-learning-insights-v15-20261010` 分支，记录 commit、Windows/浏览器版本和控制台日志；执行 `npm ci`、`npm test` 和 `node --check static/app.js`。
2. 用两个单独词库构造数据：A 有到期词、非到期错词、已掌握词、新词；B 有到期词。学习数据页选 A 时，诊断和下方困难词都只能来自 A。选「全部词库」时可显示两本词库，但主操作应先回今日选词库。
3. 分别准备最近 7 日和前 7 日的正确 / 错误记录，检查两段正确率及百分点变化；**只在一段有记录**时应显示「暂无对照」，不能显示虚假的改善 / 退步百分比。
4. 检查每个重点词后面的理由，确保「到期且曾答错」「已到期需要复习」「曾经答错」依据真实数据；关注区若无待复习和错词，应有清晰空状态。
5. 检查新词学习覆盖率与已掌握数不是同一指标；空词库显示覆盖率 0%、近期正确率 —。
6. 点「开始当前词库的今日任务」，应进入这本词库；点错题本时清楚知道会进入**全部词库错题**，不能把 B 的错误单词误当 A 的。
7. 实测 1440×900、1280×720 和浏览器 125% 缩放，检查诊断卡文本溢出、按钮焦点、中文长词库名、缩小窗口、切换词库时异步请求不串显示。
8. 关闭诊断网络请求或模拟接口 500，**其他学习统计仍能正常使用**，诊断显示错误占位而不是整页失效。
9. 检查数据库原有 `review_log`、`progress` 行数 / 关键字段未被诊断请求修改；只读功能不能创建新成绩。

**请将结果单独保存到** `docs/V1_5_INSIGHTS_ACCEPTANCE_2026-10-10.md`，按照通过、失败、未测分类，附截图、环境、具体复现步骤。没有 GUI 实测不能写成“正式验收通过”。

## V1.5 第二轮：困难词诊断 → 对应词库 → 真实回炉（2026-10-10）

### 本轮产品变更

- 统计页下方「建议关注的单词」每个词会提供明确动作：**已到期**点击「去今日复习」进入该词**所属词库**的完整今日队列；**历史错误但未到期**点击「定位错题」进入对应词库的错题本，并高亮该词。不会谎称单击就立即练到了这个单词。
- 错题本电脑端增加**词库筛选器**：「全部词库」或某本具体词库。筛选后的「开始回炉」也只从这本词库抽题；完成后点击「再来一轮」仍维持同一范围。Android 的原无参 `/api/mistakes` 与 `/api/mistakes/study` 行为不变。
- 选定某词库进行学习诊断时，如果系统建议回炉错题，按钮也会跳转**该词库**的错题本，不再丢失范围转到全部词库。
- 所有筛选、排序与跳转仅使用已有单词 ID、词库 ID 和学习记录；不改变复习周期计算规则，也不会自动删除或清零错题。

### 补充实测场景

1. 建立 A、B 两本词库，分别录入错题（A 2 个、B 1 个）。学习数据页选择 A，若仅有 A 的错题而无到期任务，建议动作应为「查看当前词库错题」，进入错题本后只能显示 A 的两条。按「开始回炉」也必须只有 A 的词，完成后「再来一轮」仍不出现 B 的词。
2. 返回统计页，切换「全部词库」。关注词里出现 B 的未到期错词，点「定位错题」，应跳到 B 的错题本并高亮对应单词；能够看到该词的实际错误次数和释义。
3. 对 B 词库制造一条到期记录，从「建议关注的单词」中点击「去今日复习」，应进入 B 的**今日完整队列**，完成后回到今日页应默认选中 B。不能误以为立刻定位到了这个单词的单题练习。
4. 错题本手动从 A 切换为 B 或「全部词库」，列表数量、状态及回炉入口同步变化。删除 A 的错题后只刷新 A 的范围，不应跳回全库。
5. 输入无效的 `book_id` 参数时，后端应返回明确 400/404；无参数的旧 Android 错题列表与练习依旧含所有词库。新增回归测试见 `test/desktop-mistake-scope.test.js`。
6. 让旧版 /api/desktop/insights 临时不可用，统计主卡仍可看，原有困难词回退视图仍可打开全局错题本，不能导致统计页整体崩溃。
7. 用 1280×720 和浏览器 125% 缩放核对筛选器、重点词按钮、强制换行以及高亮行是否容易辨认；错误词释义较长时不应出现大面积横向滚动。
8. 以上实验必须使用独立 SQLite 临时库，避免在正式学习记录上制造错误和提前到期数据。提交复测报告时单独说明 V1.4 已知阻断是否被真实 Windows 复测关闭，不能用 V1.5 的绿色 CI 代替。

**目标提交物**：`docs/V1_5_INSIGHTS_ACCEPTANCE_2026-10-10.md`，记录实际操作范围、通过/失败/未测、截图、环境与复现步骤；如果 V1.4 独立复测完成，另提交 `docs/V1_4_RETEST_2026-10-10.md`。

## V1.5 第三轮：回炉结算与真实剩余任务（2026-10-10）

### 这轮增加了什么

电脑端错题回炉完成后，结算页会**重新读取本地 SQLite 的实际错题状态**，显示当前范围（所选词库或全库）还有多少个词需要回炉。这里绝不以“本轮答对数”代替“真正已掌握数”。

- 有剩余错词：显示「继续回炉剩余 N 个错词」，下一轮维持相同词库。
- 全部词达到旧系统的掌握条件：显示零剩余及「返回错题本查看成果」，不能再催用户无意义重复刷题。
- 数据读取失败：明确提示剩余错词数量无法确认，但本轮保存的学习记录保持有效，允许用户返回错题本核对。
- 不同学习流程不共享错误状态：初次体验（guidedRun）不会泄漏到错题训练；退出或连续开启第二轮后，前一轮尚未结束的卡牌状态请求不得覆盖新的学习页。
- 仍采用既有「连续答对 3 次、streak ≥ 3 才移出错题本」规则，未修改任何学习间隔。

### Agent 补充复测

1. 用 A / B 两本词库验证：A 两个错词，B 一个错词；A 回炉结算只显示 A 的实际剩余数，按钮保留 A 的 scope。
2. A 词库错词答对 **一次**后仍在错题本，结算不得宣称“已掌握”；累计连续答对达到原规则门槛后，错题数量再减少。
3. A 词库所有错词达到掌握条件后，结算页显示 **0**，主按钮返回 A 的错题本，不应继续创建空练习轮次；全库仍可有 B 的错词。
4. 打开新一轮或切到今日页时，故意延迟旧一轮的「剩余错词统计」与卡牌状态请求，确认它们不会错误覆盖新界面。
5. 首次体验 → 错题回炉应显示正常错题结算，不得误进入新手引导的默写/完成分支。
6. 人为让 `/api/mistakes` 查询失败，结算应该解释当前剩余数未能查询，而不是报成零或清空答题记录。
7. 检查缩放 125%、窗口宽度 1280、长单词和长提示文本；结算卡片不能遮盖“继续回炉”操作。
8. 所有构造的学习记录在隔离测试库进行，实际测试后记录运行 commit、浏览器、截图与失败复现步骤。

自动化回归测试：`test/desktop-mistake-scope.test.js` 通过真实 `/api/progress` 提交验证“一次答对不能移出、连续三次才移出”和多词库计数隔离。**CI 通过不等于图形界面实际验收通过。**

## V1.5 第四轮：统计口径与边界情况收尾

### 修复重点

- **未学词不等于今日任务**：诊断使用与今日页同样的各词库计划计算式：`min(remaining_new, max(0, daily_quota - new_today))`。如果今天已经学满配额而词库仍有未学词，应显示「今天没有需要继续的新词任务」，而不是虚报需要再学词；新词覆盖率仍反映全库未开始的词数。
- **没有作答记录不能显示 0%**：电脑端全局顶部、学习数据页本词库累计正确率，若还没有答题历史都显示「—」；否则百分比按真实累计作答计算。顶部明确标注**全库累计正确率**，学习数据卡片则使用当前筛选词库的口径，减少范围误读。Android 原来统计口径暂不改动。
- **快速进出统计页**：在旧的词库列表请求延迟返回时，后进入的新页面优先，旧响应不能覆写用户当前的统计筛选。
- CI 回归增加“今日配额已完成但还剩未学词”“今天可学数小于全库未学数”的真实 API 对照测试，验证学习诊断给出的待新学词数和 `/api/desktop/books/:id/today` 一致。

### Agent 请额外验证

1. 建立 **3 个单词、每日计划 1 词**的独立测试词库；今天介绍其中 1 个，余下 2 个没学。主页应表示今天已完成，学习诊断不应错误推荐继续学习 2 个；诊断可继续显示「仍有 2 词未开始」作为长期覆盖数据。
2. 建立 **3 个单词、每日计划 2 词**的词库，今天还没开始。学习诊断应推荐「今天可学 2 词」，进入今日学习接口也确实安排 2 词，不得写成 3。
3. 全新空学习数据库没有任何答题记录时，电脑端顶部的全库累计正确率和学习数据页累计正确率应显示「—」，不能写 0%；完成一次真实答题后出现正确率。
4. 页面顶部的「全库累计正确率」和当前词库的「累计作答正确率」可以不同，但必须明确标识统计范围；选择“全部词库”后结果要与顶部相符。
5. 快速从统计页切到今日页再回统计页，或切换 A/B 词库的筛选，旧请求慢时不允许覆盖新词库。建议在开发者工具网络限速下复现。
6. 使用 **独立临时 SQLite 数据库**；完成后将截图与测试结论追加到 `docs/V1_5_INSIGHTS_ACCEPTANCE_2026-10-10.md`。若实际 GUI 未测试，请如实写“未测”，不要凭 CI 推断通过。
