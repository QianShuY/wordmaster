## 一、本轮目标与已确定方向

把墨词推进到“内容可靠、复习有效、旅行有结局、全站流畅”的日常使用版本。

用户已确定：

- 词库优化面向所有保留的内置词库，不限于当前正在背的词。已学词可优先修复，但不能作为词库完工的口径。
- 默认内置中考词库替换为高考词库；四级、六级、考研、专四专八继续保留并优化。
- 首章 Boss 胜利后必须有正式结局、持久通关记录和纪念成果。
- 全站体验与性能优化作为本轮主要交付项。
- CET6 独立项目接入继续后置，不与本轮完成绑定。

本轮只制定计划，不删除词库、不修改真实学习数据、不代答、不抽卡。原先测试学习数据的重置授权已执行完毕；现在的学习、收藏和旅行记录需要保留。

## 三、A：全词库质量与高考替换

### A1. 建立统一清单

逐库统计原始行、有效词条、独立词头、重复/同形词、隔离项、音标疑点、多词性、搭配、例句及译文覆盖。审计表记录词条身份、问题、依据、修复结果和审核状态。

覆盖率分母为该库全部正式有效词条，不能只计算已学词。词头相同但词性或义项不同的条目不能靠拼写直接合并，也不能自动共用例句。

### A2. 中考替换高考

1. 先确认高考词表范围和版本。以可核验的课程标准/考试范围为边界，核对具体来源和使用条件，不先承诺固定词数。
2. 制作独立高考源数据与构建报告；教材扩展词、短语与必学词如有差异应明确标注。
3. 验证释义、词性、音标、同形词和例句后，再将默认目录中的中考入口替换为高考。
4. 实施前只读盘点旧中考词库的学习记录、自建编辑、活动计划与检查点。
5. 默认不再提供中考作为新学习入口。有旧记录或手动编辑时，将旧库保留为历史只读资料；新高考库独立建库，不能给旧 book_id 换名称和内容来冒充迁移。
6. 无旧记录、无手动编辑且无引用的内置中考内容，可在验证引用完整后移除。删除操作不波及其他词库和收藏。
7. 仅在完整词条身份及学习目标一致时评估跨库映射；不默认按同一拼写转移熟练度。若旧库是当前计划，明确提示范围已变并保留旧断点，不静默套用旧配额、目标日期或题目。

交付：高考词库、来源说明、构建审计、替换/历史资料处理结果及升级验证。高考库验收前，不先删除中考正式内容。

### A3. 全量释义、音标与例句

- 顺序：高风险问题→六级遗留→高考正式库→四级、考研、专四专八逐库推进。每批都报告全库覆盖变化。
- 保留原始来源与修订依据；多词性按义项整理，搭配单列；修复内容错误，不能只把错误文字排得更整齐。
- 每个正式词条至少有一条对应常用义的英文例句及准确中文译文。多词性/同形异义条目按实际义项匹配；关键易混义增加对照例句。
- 例句目标是全量有效覆盖，不用通用励志句凑数，不要求把所有偏义一次写完。区分“已生成”“规则检查通过”“语言审核通过”，未经审核不计入完成覆盖率。
- 自编例句或使用明确可用的授权内容；核对语言依据和来源使用条件，不能批量搬运词典例句。
- 内容补丁只改核验字段，保留既有词条身份；用户自建与手改内容不能被内置补丁覆盖。当前仅对六级启用的分组展示，在其他库验证通过后扩展。
- 隔离项逐条判定：修复后恢复、确认不属于该词表而排除，或继续隔离并注明原因。不能用降低分母隐藏未完成问题。

验收：每库有独立报告；正式词条结构有效率 100%，至少一组已审核双语例句覆盖率 100%；无法确认的内容不得进入正式题池。语言审校须有逐条状态与针对高风险义项的人工复核，脚本通过不等于审校通过。各库分批交付，不把六级首轮完成称作全词库完成。

## 四、B：复习可靠性与学习反馈

保留现有新词三轮、旧词两步复习与间隔安排，先验证和修复，不轻易再增加一轮机械作答。

| 场景 | 验收行为 |
| --- | --- |
| 旧词选对但未拼写 | 仍为未完成复习，不延长间隔，也不能领取旅程通关 |
| 任一步答错 | 按强化规则重复；提示后的答对不冒充独立掌握 |
| 连续错误 | 有解释、再学和可恢复的强化状态，不能永久困在无提示重测 |
| 刷新、退出、重开 | 原词序、阶段、错误次数与后台进度一致 |
| 跨日、长时间未学、逾期 | 重新核对真实到期任务；无重复推进、任务丢失和错误日期 |
| 网络失败、重复点击、请求重发 | 给出重试状态；同一次答案不重复结算 |
| 内容更新或词库切换 | 保留合法进度，不将旧题错绑到新词条 |

补充学习反馈：在学习页显示错误次数、待强化原因和下次复习；在数据页区分当天练习正确率与跨日独立回忆，不把连续三次答对写成长期掌握。

交付：隔离数据库的跨日回归报告、真实界面的只读/不代答验收，以及发现问题的修复。推进测试时间使用可控时钟或测试数据，不修改系统时间和真实复习日期。

## 五、C：第一章 Boss 与正式结局

### C1. 胜利先可靠保存

- 校验真实旅程资格；正式战斗与演示/预览分开，预览不得领取通关和奖励。
- 当前战斗结果主要保存在本地，正式结局需要后台可验证的战斗会话和胜利条件，不能仅接受前端传入“胜利=true”。
- 保存章节、正式战斗会话、胜利时间、结局版本、奖励领取状态；同一首次通关具有唯一约束。
- 刷新、关闭、重复提交和中断后继续均能恢复；结算失败可重试，不能丢结果或重复发奖。

### C2. 给两周旅程一个收尾

建议首章结局：守卫败退，桥上的雾散开；沿途获得的信笺拼成完整来信，解释本章关键线索，让玩家看到自己的抵达改变了什么。先解决本章悬念，再留下下一段旅程的轻微伏笔。

呈现为短演出→可阅读结局→个人旅程收据→纪念成果，不再堆一个数值弹窗。演出可跳过、文本可回看；减弱动态时仍能完整理解结局。不要求生成第二章完整地图才能完成首章。

收据使用真实数据：出发/抵达日期、实际完成的旅程日、学习与复习成果；不编造冒险时长和英语等级。区分全站数据与本章数据。

### C3. 纪念与后续入口

- 至少交付第一章通关印章和一项专属纪念收藏；提前明确与现有卡册的关系，不借机新增复杂货币。
- 首次通关奖励只发一次；重战用于挑战和回看，不刷学习记录、不改变复习间隔。
- 地图显示已完成状态；旅行首页出现章节收尾与结局回看入口。下一章尚未可玩时明确“尚未开放”，不提供空入口。
- 失败保留旅程进度，日常背词不受 Boss 锁定；最初来信与逐步揭示线索的神秘感继续保留。

验收：真实资格→正式挑战→胜利→存档→结局→奖励→重开仍在；预览、重复结算、失败后复起和断线重试分别验证。

## 六、D：全站体验与性能专项

### D1. 体验统一

覆盖今日、词库、学习/复习、数据、卡册、旅行入口、地图、营地、战斗和结局：导航与返回、陈列主题继承、标题层级、按钮/弹窗、加载/空态/错误、键盘操作与焦点管理。

保留已经确认的审美：纸质旅行手账、主题壁纸、完整展开的地图、小符号关卡、克制的水面与烟雾、独立飞行的黑色大雁、可控的冒险轻音乐。环境噪声不恢复；不为优化重画已认可的地图或重做演出。

学习内容优先：新词直接给释义；回忆时不泄露答案；首次打开今日页，计划和当下任务位于主要可见区域。不同窗口尺寸不会把主要操作推到屏幕外。

### D2. 先测再优化

基线固定机器、窗口和数据规模，分别记录冷启动/热切换、主题切换、词库搜索、学习继续、地图进入、战斗演出，以及连续切换后的内存/资源情况。

记录：首个可操作内容时间、主线程长任务、动画帧耗时、资源体积与解码、数据库/API 延迟。缓存冷/热分别说明，至少重复 5 次并保留范围；不能只凭“感觉顺滑”宣布完成。

| 优化方向 | 具体检查 |
| --- | --- |
| 大图 | 合适分辨率和格式、延迟加载与解码、复用缓存；画质对照后采用 |
| 页面切换 | 避免重复初始化、重复请求和等待装饰资源；加载中有即时反馈 |
| 词库与数据库 | 大库搜索、分页、查询计划；有证据再加索引或调整查询 |
| 动画 | 隐藏页暂停、清理监听/计时器、减少大面积模糊与重绘；支持减少动态 |
| 音乐 | 用户控制开关与音量，离开/隐藏正确暂停，不重叠播放 |
| 长时间使用 | 多次导航和开关弹窗后不持续累积资源，不丢断点 |

暂定目标（以用户当前 Windows 机器的发布构建测量）：已加载的主栏目切换在 200ms 内给出可见反馈；普通操作不出现可复现的 500ms 以上主线程阻塞；地图动画以 60fps 为目标，持续明显掉帧时提供自动/手动减弱动态。冷启动先测基线再设有依据的绝对预算，不伪造毫秒级成果。

验收：优化前后相同条件对照；主要瓶颈的指标改善且无内容/画质/交互退化；大词库和日常数据场景均通过。开发浏览器结果不能替代 Windows 发行包结果。
