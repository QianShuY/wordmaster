# 墨词词条与数据页：第二轮视觉纠偏

日期：2026-09-28  
状态：用户否决当前第二轮视觉样例。本文供用户转发给实现 agent；优先于之前方案中的布局建议。先做样例，不扩展全词库。

## 用户反馈

这轮把原本紧凑的应用改成了过于空旷的展示页。学词、拼写和数据页的核心信息散在大面积空白里，阅读与操作效率下降。请把目标收回到**原有界面的精修**：保留已修正的数据和排版问题，撤回大幅改变页面结构的设计。

## 1. 学词页

- 截图里的 `arbitrary` 位于偏左上方，下面和右侧留下大面积空白；“查看释义”成为孤立的大黑按钮。不要再用全宽、无边界的 `dictionary-stage` 展示方式。
- 恢复居中、宽度受限的学习区域。桌面以约 640–720px 的内容宽度为起点，卡片高度由内容决定；单词、音标、词性、释义入口和判定操作要形成一个紧凑整体。屏幕宽时也不能把信息摊满整个画布。
- 释义展开后继续显示词头和音标；多词性、多义项分组清楚即可，不要用大块空白或“盒中盒”填充。无需追求新的全屏词典页风格。
- 保留已经完成的词形清理：例如大标题显示 `cardinal`，小标签区分原词条，音标独立、朗读正确。保留原词条 ID、复习进度和拼写判题逻辑。

## 2. 拼写页

- **用户明确指定：删掉上方独立的输入框，把下方字母格放大，作为页面上唯一可见的拼写输入区。** 当前 `static/app.js` 同时渲染 `.spell-entry > #spellInput` 和 `#slots`，用户输入 `aes` 会在两处重复出现；这是本轮必须消除的问题。不要通过缩小其中一个框继续保留两个可见区域。
- 下方字母格需真正可输入：点击/触摸任意位置即可聚焦同一区域中的真实 HTML 文本输入控件，能唤起手机软键盘；键盘输入、粘贴、退格、光标定位、输入法组合和屏幕阅读器均可用。实现方式可用“真实 input 与字母格合成一个控件”，但对用户只能看到**一个输入区、一次输入内容、一个焦点状态**。不能把真实 input 隐藏到无法聚焦的位置，也不能退回只监听键盘事件的假输入。
- 字母格适度放大并按可用宽度排列，长词和词组在 360px 手机上不横向溢出；空格、连字符和撇号仍能正确输入与判题。输入错误时只在这一处反馈，不再复制一遍答案。
- 缩小卡片空白和纵向间距。词性、释义、输入、反馈、操作按钮应连续阅读；常见桌面视口中不需要大幅滚动才能看到按钮。不要删除“跳过稍后回炉”或“听发音”。
- 与学词页使用同一套宽度、边距、按钮规格，避免一个页面全屏、另一个页面厚重悬浮卡。

## 3. 学习数据页

- 当前 7 天柱图只有两根柱子孤零零地靠右，热力图缩得很小，下面又新增一张横跨整页的逐日正确率长表。不要用大空白来表示“没有数据”。
- 保留有宽度约束的统计卡片网格。7 天学习量固定按 7 个日期槽组织，有数据的柱子落在对应日期，空日用克制的基线或日期标签占位；图表区域随内容保持适度高度。热力图在桌面与手机上都应可读。
- 近 30 天只有少量作答日时，正确率直接在**原正确率模块内**显示紧凑记录：日期、正确/作答、百分比；不再另开一张全宽长表，也不画四个点占据整块空白。数据足够时再使用按真实日期定位的折线。
- 数字字体与基线对齐的改进保留；统计数字、单位和分母的层级继续统一。

## 必须保留的已有成果

- 干净词头、音标和同形词的安全映射；多义项可读排版；**单一区域内的真实输入能力**；数字等高对齐；图表不伪造日期间隔。
- 键盘操作、手机输入、减少动态效果、隐藏卡与抽卡规则、现有单词和卡牌 ID。不要写入生产数据库，验证使用隔离副本。
